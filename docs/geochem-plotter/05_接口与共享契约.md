# 接口与共享契约（schema 1.1）

本文件规定双方必须对齐的最小合同。Qoder 在 Q01 将其转成可执行 Pydantic 模型、OpenAPI 和 JSON Schema；Trae 由 schema 生成 TypeScript 类型，禁止双方另建不同命名的数据模型。

与[15_v2接口与任务增补](15_v2接口与任务增补.md)共同执行：15补齐样式、坐标、图件、真实写盘和启动器合同。主产品基线为[正式任务书v2](../../GeoPlot_科研绘图工具_正式任务书_v2.md)。首次实现直接使用1.1；1.0只用于已有项目迁移说明。

## 2. 通用约定

- API 前缀 `/api/v1`，仅绑定 127.0.0.1；开发允许配置本机前端端口，生产前端与 API 同源。
- ID 使用无语义字符串，不把 Windows 文件路径作为 ID；数值 JSON 为 number 或 null。
- 时间使用带时区 ISO 8601，界面用本地时间显示；数据快照哈希使用规范序列化后 SHA-256。
- 所有变更响应返回 revision；保存已有对象带 expected_revision，不匹配返回 409。
- 错误格式：`{error:{code,message,field_errors:[{path,message}],details,request_id}}`。message 可中文，不让前端解析英文异常文字。
- 可用错误码：UNSUPPORTED_FILE、MAPPING_REQUIRED、UNIT_UNCONFIRMED、DUPLICATE_COLUMN、NORMALIZER_INCOMPLETE、REFERENCE_INVALID、STALE_REVISION、EMPTY_SELECTION、NO_VALID_POINTS、EXPORT_FAILED、PROJECT_DATA_MISSING。
- 分页按稳定 analysis_id 加排序字段组合，默认 100 条、上限 500；游标/页码策略固定一种，首版用 offset/limit 并绑定 dataset_versions。

## 3. 核心对象

### Dataset / AnalysisSummary

Dataset 包含 `dataset_id,version,label,role,file_id,sheets,counts,mapping_version,created_at`。counts 分别列 physical_rows、accepted_analyses、quarantined_rows、skipped_rows、linked_derived_rows，彼此定义和是否互斥须在 schema 描述中写清；commit 报告对每个原始数据行恰好赋一个 disposition。

AnalysisSummary 包含 `analysis_id,sample_id,raw_name,parent_sample,subsample,mission,batch,material_type,mineral_group,phase,rock_type,citation,source:{file_id,sheet,row},quality_flags`。classification 推断证据从详情端点获取。

### ColumnMapping

列身份为 `{sheet,column_index,header_raw}`；重复表头也唯一。映射为 `{target,analyte,chemical_form,unit,value_state,channel,related_column_index,reference_id,confirmed}`。target 可为 metadata / measurement / uncertainty / detection_limit / ignored；空表头不能自动配成元素。

导入配置包含 header_row、data_start_row、block_ranges、classification_rules、row_exclusions、duplicate_policy、reference_maps；任何重映射写新版本。

### SelectionSet

```json
{
  "name": "Apollo 74235 全岩",
  "dataset_versions": [{"dataset_id":"ds_apollo","version":"1"}],
  "mode": "snapshot",
  "filter": {
    "mission": ["Apollo"],
    "material_type": ["whole_rock"],
    "sample_search": {"mode":"parent","text":"74235"}
  },
  "include_ids": [],
  "exclude_ids": []
}
```

创建时基于 filter 解析全体候选，再并入 include_ids、去掉 exclude_ids，去重后生成 resolved_ids 与 selection_hash。snapshot 固定 ID；dynamic 保存规则但每次 compute 必须再次冻结 resolved_ids 和数据版本。样品数量统计不能由前端猜。

### Expression

判别联合类型：

```text
measurement: {kind:'measurement', analyte, chemical_form:'element'|'oxide'|'isotope_ratio'|'index', unit, channel?}
normalize:   {kind:'normalize', value:Expression, reference_id, reference_version}
ratio:       {kind:'ratio', numerator:Expression, denominator:Expression}
add:         {kind:'add', operands:Expression[]}
constant:    {kind:'constant', value:number, unit:string}
```

首版计算兼容范围见 03；isotope_ratio/index 仅已验证来源字段展示，不自动计算。禁止无字段约束的自由脚本。

### PlotScene

是所有绘图适配器共用的计算结果，包含：

```text
scene_id, schema_version, request_id, spec_hash, scene_hash, plot_revision
resolved_selections: [{selection_id, selection_hash, analysis_ids, dataset_versions}]
reference_snapshots: [{ref_id,version,hash,values,units,citation,verification_status}]
axes: {x:{label,unit,scale,range,ticks},y:{label,unit,scale,range,ticks}}
series: [{series_id,layer_id,analysis_ids,sample_ids,label,style,
          points:[{point_id,analysis_id,x,y,x_error,y_error,quality_flags,provenance}],
          break_at_missing:boolean}]
diagram_geometry, legend, layout, font_manifest, warnings
counts: {selected_analyses,valid_analyses,excluded_analyses,distinct_samples,physical_identity_unknown,plotted_points,out_of_view,hidden_by_style}
exclusions: [{analysis_id,analyte?,reason_code,source_cells}]
software_version
```

REE 每条分析一个 series，x 为分类序号且 ticks 保存元素名，缺值用 y=null 保留位置，`break_at_missing=true`。scatter 每个样式组一个 series，每点带 analysis_id。所有 log 数值存**未取 log 的正数**，由渲染器的 log scale 显示，禁止二次取 log。

所有序列为确定顺序。scene_hash 对科学数据和渲染配置计算，不把 request_id、创建时间混入；同配置同数据重算应一致。provenance 包含原始值、单位换算、参考值、原单元格，可根据大小分为 summary 和可下载详情。

## 4. HTTP 合同

| 方法 / 路径 | 输入 | 输出 / 行为 |
|---|---|---|
| GET /health | 无 | status、app_version、schema_version |
| POST /imports/scan | multipart file | 202 `{job_id}`；只扫描不入库 |
| GET /jobs/{job_id} | 无 | status=queued/running/succeeded/failed/cancelled/interrupted；phase、processed、total、result、error |
| POST /jobs/{job_id}/cancel | 无 | 请求取消，事务回滚后 status=cancelled |
| GET /imports/{preview_id} | scan result 的 ID | sheets、columns、head_rows、suggested_maps、issues、overlap_candidates |
| POST /imports/{preview_id}/commit | mappings、roles、reference_maps、duplicate_decisions | 202 `{job_id}`，成功 result 含 datasets/import_report |
| GET /datasets | 无 | 数据集列表和版本 |
| POST /datasets/query | dataset_versions、filter、sort、offset、limit | rows、total、material/mission counts、query_hash |
| POST /datasets/facets | dataset_versions、filter | 各筛选维度及数量；以全部筛选上下文计算 |
| GET /analyses/{analysis_id} | 无 | 元数据、全部测量/误差/LOD、来源和修订历史 |
| PATCH /analyses/batch-metadata | dataset_version、analysis_ids、changes、reason | 新 dataset_version、updated_count；旧版本可读 |
| POST /selections | SelectionSet 输入 | selection_id、resolved_count、distinct_samples、selection_hash |
| PATCH /selections/{id} | expected_revision、变更 | 新 revision 与解析后的计数 |
| GET /references | 无 | 元素覆盖、单位、版本、出处、验证状态 |
| POST /references | 自定义值表与元数据 | ref_id、version、校验结果；不正值 422 |

Mapping 模板随项目保存并通过 GET/PUT projects 复用；无需首版另建复杂模板服务。数据集 deletion 不属于首版常规操作，避免误删已有图依赖。

## 5. 任务和一致性

后台任务持久化状态到 SQLite；首版可用单进程工作队列，不依赖 Redis/Celery。重启时未结束任务标 interrupted 并可重试，不能永远 running。前端必须呈现 interrupted 终态与重试入口。

计算请求带递增客户端 request_id；Trae 丢弃过期回包。后端返回 plot_revision/spec_hash，旧 scene 不可标为当前图。Export 请求只接受已存在 scene_id；数据变化不能导致后台在导出中重新查询“最新”选样。

所有筛选在后端按版本执行；前端列表分页不影响实际选择。多个 layer 同一 analysis 可有不同样式，但总计数分别标明“图层重复使用”与“独立分析”，不能误报独立样本增多。

## 6. 输入与项目包边界

仅接收 .xlsx 和定义好的 CSV，首版不执行宏，不执行外部链接或任意公式。公式使用缓存仅作为来源值，已支持派生量用内核重算。限制上传 100 MB、解压后 1 GB/200,000 行/2,000 列，超过时给明确错误；本工作簿在范围内。限制可通过本地配置调节但须提示资源影响。

文件存储使用内部 UUID，避免同名覆盖和路径穿越；项目包解压前校验条目路径，拒绝绝对路径和 `..`。导出 CSV 对以 =、+、-、@ 开头的**文本**做公式注入防护；负数测量仍导出数值，不改变科学值。用户数据不得调用 LLM 或上传第三方服务。

## 7. 契约变更流程

Qoder是contracts及`docs/progress/CONTRACT_CHANGELOG.md`唯一写入负责人。Trae在自己的`docs/progress/TRAE_CONTRACT_REQUESTS.md`提交字段需求、原因、受影响UI和fixture；Qoder处理后更新schema/fixtures/版本及变更日志，双方跑契约测试。不能只改mock而不改后端。
