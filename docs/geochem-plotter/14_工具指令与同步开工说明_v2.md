# 给Qoder、Trae的指令与同步开工说明 v2

> 2026-10-29更新：以下为初建基线/交接模板，非当前验收状态。已有代码按[18返工任务书](18_pyrolite绘图内核返工任务书.md)执行；绘图合同以该增补为准，不从零重建。当前复制指令见[Qoder](QODER_pyrolite返工指令.md)和[Trae](TRAE_pyrolite返工指令.md)。

## 1. 现在能否同时开工

**可以。Qoder先建立共享合同和服务，Trae同时做布局和合同审阅。** Q01的schema1.1和fixtures通过校验后，双方再并行实现完整功能；真API可用即接入，最后对同一个候选交付包验收。

优先采用两个独立工作副本/分支；若工具只能共享D:\moon，同一Git目录不得同时checkout，两边只能编辑各自目录。Qoder负责backend/contracts/launcher/scripts/packaging/数据包，Trae负责frontend。文档变更写各自进度文件，合同由Qoder单人维护。

先执行Q01：把合同写成Pydantic/OpenAPI/JSON Schema和合成fixtures，包含Figure/Revision/Export、独立点/线alpha、轴格式和RuntimeStatus。通过契约校验后生成docs/progress/CONTRACT_READY.json，填真实schema/fixtures哈希与验证命令，再执行Q02–Q12。合同变更写CONTRACT_CHANGELOG.md并更新fixtures，不只改后端字段。

## 3. 直接发给Trae

```text
请在 D:\moon 开发GeoPlot中文前端。先读根目录 GeoPlot_科研绘图工具_正式任务书_v2.md；再读docs/geochem-plotter下01–05、07、13、15、16、08、09和11。Qoder负责服务、科学计算、共享schema、写盘、启动器与打包，你只负责frontend及你的进度文件，不处理AstroMat。

现在可执行T01的页面布局、导航和合同审阅；在docs/progress/CONTRACT_READY.json为ready且schema/fixture哈希与实际文件一致后，用生成的TypeScript类型完成T02–T11。早期mock只能使用合同fixtures，不能自造与后端不同的字段；真API一可用就联调，T08/T09关闭mock。需要改合同写你自己的docs/progress/TRAE_CONTRACT_REQUESTS.md，由Qoder落实到CONTRACT_CHANGELOG.md，避免共写文件。

工作台必须有内置库/上传、任务/材料/矿物/母样品/测点选择、独立对比图层、变量编辑器、图件库与导出记录。筛选不自动更改投图选择；跨页勾选依赖analysis_id。后端计算单位、比值、标准化和坐标，前端不能复制一套科学计算。

做完整Excel式图表编辑：双击横纵轴编辑范围、log/linear、刻度、数字格式和反转；双击点打开系列格式；当前层/全部层/选中分析三种范围；9种形状、实心/空心、填充/边框颜色、1–20pt直径、独立点/线透明度。UI透明度0%=不透明、100%=完全透明；内部alpha只应用一次。图例/注释可编辑，测量点坐标不能拖改。所有设置写入PlotSpec→Scene并进入导出，不能只改DOM。

导出必须选择本机文件夹、显示真正保存路径与文件列表；检查PNG/PDF/SVG真实文件，不把浏览器下载动作当写盘成功。图件可保存版本、重开编辑，导出历史可打开目录、发现文件缺失、按原版本重导。重启后无需重传数据，所有设置恢复。

按照11依赖完成T01–T11。Qoder出候选便携包后，用同一包验证已安装/未安装Python和Node的Windows10/11四格；两类环境使用相同启动按钮。负责真实浏览器流程、交互和论文图视觉验收，配合Qoder检查磁盘文件和恢复；不能只跑build。

每完成一项记录文件、测试命令/结果、截图或产物路径、缺陷和下一步到docs/progress/TRAE_HANDOFF.md。最终按08+16提交86项P0覆盖情况及四图视觉证据；未执行项标未验证，不写“全部通过”。
```

## 4. 阶段信号：不用用户反复口头传接口

Qoder在Q01创建以下文件，初始内容明确为未准备好：

```json
{
  "status":"not_ready",
  "schema_version":"1.1",
  "schema_sha256":null,
  "fixture_manifest_sha256":null,
  "backend_commit":null,
  "verified_commands":[],
  "provided_endpoints":[]
}
```

`docs/progress/CONTRACT_READY.json`只有在schema、fixtures与契约测试通过后改为ready，填真实值；Git尚未初始化时先由Qoder建立仓库，原数据加入ignore。Trae检查实际文件哈希，不能只相信ready文字。新合同版本撤销旧ready并重新校验。

| 信号 | 产生者 | 实际条件 | 此后可做 |
|---|---|---|---|
| CONTRACT_READY.json | Qoder，Trae核对 | schema1.1、合法/非法fixtures与类型测试通过 | 按稳定字段并行开发 |
| SCIENTIFIC_FLOW_READY.json | Qoder | 真数据查询、选择、计算、Scene和数值oracle通过，含命令/样例/hash | Trae关闭对应mock做真闭环 |
| RELEASE_CANDIDATE_READY.json | Qoder | 实际便携包路径、版本、SHA-256、UI构建版本、待测项 | 双方测试同一候选包 |
| RELEASE_ACCEPTANCE.md | 双方 | 08与16覆盖、四格运行、真实文件/图件恢复/视觉通过 | Qoder发布正式交付包 |

阶段表与具体前置见[总任务清单](11_总任务清单.md)。交接文件无需自动消息服务；同目录读取即可，独立副本由Qoder集成提交后Trae同步。不得在同一个文件上同时改动。

## 5. 最值得注意的事项

1. 科学正确性先于界面美化：数据单位、材料、analysis身份和参考值不明确时，显示原因，不猜、不补0。
2. 选择的是分析记录；同名不等于同一测点。原始/汇总和CE派生视图有重叠，不能重复投图增加n。
3. 保存项目、保存图件版本、导出图像是三个动作；每项都需要实际可恢复的产物。
4. 样式必须进入Scene；点径是pt，透明度只应用一次，预览和导出分别检查。
5. 可运行源码不等于可交付包；已有Python/Node不能掩盖漏打包依赖，也不能污染便携运行时。
6. 验收缺环境就标未验证，不能拿开发机“能跑”替代四格证据；预发布状态不得叫正式交付。

用户最后可按主任务书第13节亲测：选择74235→画散点→改轴→蓝色6pt空心三角、50%透明→保存→导出三格式→资源管理器打开→停止重启→恢复并重导。
