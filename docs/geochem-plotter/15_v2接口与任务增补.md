# v2 接口、数据结构与任务增补（schema 1.1）

与 [正式任务书v2](../../GeoPlot_科研绘图工具_正式任务书_v2.md) 一起执行。05为基础合同，本文件补充其缺失对象并替换v1的简化样式和坐标字段；不允许前后端各自做兼容猜测。

## 1. 样式字段替换

PlotSpec.schema_version固定为`1.1`；每个layer包含`style`和`analysis_style_overrides`。style完整定义：

```json
{
  "marker_shape":"circle",
  "marker_fill":"solid",
  "marker_fill_color":"#D55E00",
  "marker_edge_color":"#D55E00",
  "marker_size_pt":3.5,
  "marker_edge_width_pt":0.35,
  "marker_alpha":1.0,
  "line_color":"#D55E00",
  "line_width_pt":0.8,
  "line_dash":"solid",
  "line_alpha":1.0,
  "connect":false
}
```

枚举和范围按正式任务书第6节。scatter connect=false；REE/spider connect=true但缺值仍断线。TAS散点不连线。`analysis_style_overrides`为`{analysis_id: Partial<Style>}`；仅允许该layer选择集中的ID，其他ID拒绝，不默默忽略。

解析顺序为预设→layer→analysis override。Scene存每point/series最终样式。废弃父层`opacity`，否则可能重复乘alpha；v1到v1.1迁移时将opacity复制为marker_alpha和line_alpha一次，并删除旧键。marker旧`triangle`统一映射triangle_up，其余不认识值要求明确映射，不猜。

点形适配表：circle→Plotly circle/Matplotlib o；square→square/s；triangle_up→triangle-up/^；triangle_down→triangle-down/v；diamond→diamond/D；plus→cross/+；cross→x/x；star→star/*；hexagon→hexagon/h。空心由fill=open和边框颜色实现，不能靠白色填充假装透明空心。

`marker_size_pt`是名义直径。Matplotlib scatter使用名义面积`size_pt²`并验证各marker的尺寸映射；Line2D使用markersize=size_pt。Plotly先按pt×96/72换CSS尺寸，再乘预览缩放因子。字体和线宽也按相同预览比例处理。最终导出仍按pt。测试测量允许轮廓边界和抗锯齿引入微小像素差，但不能出现4与16倍的量纲错误。

## 2. 坐标字段替换

每个轴独立使用以下对象；旧`x_scale/y_scale/x_range/y_range`通过一次性迁移转成`axes.x/y`，不要同时保存两套可写字段。

```json
{
  "scale":"linear",
  "range_mode":"manual",
  "min":0,
  "max":0.5,
  "reversed":false,
  "tick_mode":"step",
  "tick_step":0.1,
  "log_exponent_step":1,
  "number_format":"fixed",
  "decimal_places":2,
  "significant_digits":3,
  "title_override":null,
  "title_font_size_pt":7,
  "tick_font_size_pt":6,
  "major_grid":false,
  "minor_ticks":false,
  "tick_direction":"out"
}
```

range_mode=auto时min/max=null；manual要求有限min<max。scale=log10要求min>0；UI的“log”统一转log10，禁底数混淆。tick_mode auto/step；线性step>0，log使用log_exponent_step整数1–6。数字格式auto/fixed/scientific；字号/刻度范围按正式任务书。scale=category仅用于REE/spider X，另存`category_order/visible_categories`，不接受数字min/max。

对数轴所有Spec/Scene的min/max和ticks存原量纲正数。Plotly适配器仅将轴range转为`[log10(min),log10(max)]`，例如0.1–1000变成[-1,3]；点数组不取log。relayout返回指数范围时先10的幂还原，再让用户提交视野。Matplotlib直接接原量纲边界。此区别来自[Plotly官方轴规范](https://plotly.com/javascript/reference/layout/xaxis/#layout-xaxis-range)，测试必须覆盖，不能笼统禁止适配层所有log10。

类别轴：category_order必须等于variables.elements的无重复排列；visible_categories只能是其中连续子序列，默认全部。更改顺序同步更新两者，X范围编辑只修改可见子序列；前后端拒绝两个元素顺序冲突的Spec。layout.legend的position非custom时anchor_x/y=null；custom时均为0–1。该锚点以整幅画布左下为(0,0)，不直接冒充Plotly绘图区paper坐标；适配器需按Scene固定边距换算。

`viewport`是临时浏览状态，默认不入revision；点击“将当前视野用于导出”后写axes manual范围并触发重算。layout.legend增加`{position:'right'|'inside'|'custom',anchor_x,anchor_y}`，custom相对整幅画布0–1；annotations包含id、text、anchor_x/y、font_size_pt、color，需支持编辑/删除。

## 3. 记录对象

| 对象 | 字段 |
|---|---|
| Figure | figure_id、project_id、name、chart_type、thumbnail_artifact_id、current_revision、archived、created_at、updated_at |
| FigureDraft | figure_id、expected_revision、spec、selection_snapshots、saved_at；可变草稿，3秒防抖写入 |
| FigureRevision | figure_id、revision_id、revision_number、spec、scene_id、source_versions、reference_snapshots、resolved_analysis_ids、created_at、content_hash；不可变 |
| OperationRecord | operation_id、figure_id、draft_or_revision、timestamp、action、changed_fields、before_summary、after_summary、request_id |
| ExportRecord | export_id、figure_id、revision_id、scene_id、scene_hash、export_seq、formats、size_mm、dpi、background、export_root_id、relative_dir、state、files、error、timestamps |
| ExportFile | artifact_id、filename、format、byte_size、sha256、absolute_path、exists；exists在查询详情时检查 |
| ExportRoot | export_root_id、absolute_path、display_name、selected_by_user_at、writable_check |
| RuntimeStatus | app_id、app_version、profile_id、instance_id、pid、process_started_at、state、base_url、active_jobs |

ID/修订术语固定：plot_id只标识PlotSpec对象；Figure通过draft/spec引用它，不拿plot_id作figure_id。Figure的metadata_revision只用于重命名/归档的并发控制，draft_revision只用于编辑草稿，revision_number/rid用于不可变保存版本；API中的expected_revision按对应端点资源解释。各字段在schema分别定义，不能用一个revision计数器同时驱动三类写入。

新增Figure字段metadata_revision、current_revision_id（未保存为null）；FigureDraft增加draft_revision。POST figures返回metadata_revision=1、draft_revision=1、current_revision_id=null。PATCH Figure的expected_revision匹配metadata_revision，PUT draft匹配draft_revision；创建revision必须指定其依据的draft_revision及scene_id，二者spec_hash一致。保存后不清空编辑草稿，草稿基于该保存版本继续编辑。

样本数继续分selected/valid/excluded；新增`out_of_view`、`hidden_by_style`、`physical_identity_unknown`。范围裁切、alpha=0不等于科学无效，不能计入质量排除。

图件保存版本号与导出目录号分离：revision_number=4的图可多次导出到v0001/v0002目录；export_seq只表示此图的导出次数，记录里都指向revision4。

## 4. 新增/修订API

所有路径在`/api/v1`下，schema版本升级不改变此前路由前缀。保持05的错误结构。

| 方法/路径 | 输入 | 返回与要求 |
|---|---|---|
| GET /catalog/builtin | 无 | 本期6个目录项、参考资源、已登记数据版本和需确认事项 |
| POST /catalog/{data_id}/attach | project_id、mapping_profile_id | 绑定内置库到项目；幂等，不重新复制分析行 |
| POST /figures | project_id、name、spec | figure_id、draft、metadata_revision=1、draft_revision=1、current_revision_id=null |
| GET /figures | project_id、archived=false | 图件列表和缩略图 |
| GET /figures/{id} | 无 | 图件+当前草稿+已保存版本信息 |
| PUT /figures/{id}/draft | expected_revision、spec、selection_snapshots、operation | 防抖保存草稿，返回新draft_revision；409不覆盖 |
| PATCH /figures/{id} | name或archived、expected_revision | 重命名/归档，不删除历史 |
| POST /figures/{id}/revisions | draft_revision、scene_id | 校验spec_hash一致后创建或复用不可变revision |
| GET /figures/{id}/revisions | 无 | 版本列表 |
| GET /figures/{id}/revisions/{rid} | 无 | 完整不可变快照 |
| POST /figures/{id}/restore | revision_id | 生成新草稿/新保存版本，原版本不变 |
| GET /figures/{id}/operations | offset/limit | 操作记录 |
| POST /desktop/choose-export-root | project_id | 202 job；启动器主线程显示系统选目录，成功返回export_root_id和路径，取消返回cancelled |
| POST /export-roots | project_id、用户明确输入的absolute_path | 检查并登记用户目录，返回export_root_id |
| GET /export-roots | project_id | 已选目录列表/默认目录 |
| POST /exports | figure_id、revision_id、scene_id、formats、dpi、background、export_root_id、include_bundle | 202 job；所有ID/哈希一致；规格尺寸来自冻结Scene，不允许另传不一致宽高 |
| GET /exports | project_id或figure_id、offset/limit | 历史含失败记录，不仅成功记录 |
| GET /exports/{id} | 无 | 完整记录、文件存在状态与实际路径 |
| POST /exports/{id}/open-folder | 无 | 只打开此记录关联目录，失败报告原因 |
| POST /exports/{id}/reexport | export_root_id可覆盖 | 用原revision创建新job和export_id，不覆盖旧输出 |
| GET /runtime/status | 无 | 当前实例和任务状态 |

实际文件下载继续用GET /artifacts/{id}。Native目录选择、打开目录、停止服务仅限本地应用请求，使用启动器实例token与同源校验；不把接受任意shell命令的接口开放给网页。目录选择UI必须在native主线程队列执行，不从后台线程直接创建Tk窗口。

原生交互走启动器与服务之间的私有IPC：Windows命名管道仅当前登录用户可访问，消息包含protocol_version、instance_id、request_id、action和受限payload，action只允许choose_export_root/runtime_status/stop。目录选择结果经同一request_id回传；启动器退出或取消返回明确错误，不无限等待。服务HTTP不暴露任意进程终止或shell执行；停止按钮由启动器发出受控stop，等待/取消策略随消息传入。

## 5. 导出与恢复的状态合同

ExportRecord.state：queued→rendering→verifying→committing→succeeded；任何阶段可failed/cancelled，重启未完成标interrupted。Job总状态可以映射为running+specific phase。

成功条件：临时目录全部目标文件已生成且可解析、哈希已算、正式目录已完成同盘重命名、数据库成功记录已持久化。使用唯一export_seq预留；DB提交失败时在下一次启动对目录manifest恢复登记或标记orphaned待恢复，不将文件悄悄丢弃，也不产生假的成功记录。

每个正式目录有export_manifest.json，包含export_id和完整文件哈希。便携包升级不清空图件、操作、导出记录。下载副本失败不更改原本“已保存到本机”的状态；UI分别显示本机保存和副本下载状态。
